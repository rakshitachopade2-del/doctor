The production smoke check used a new temporary database and a randomly generated administrator password. It verified administrator bootstrap, disabled demo mode, absence of fictional doctor profiles, a Secure session cookie, built SPA route serving, security headers, empty administrator reporting/expense tables, private investigation worklist/owner reads on a fresh database, unauthenticated worklist rejection, private CSV export access, and a synthetic patient-facing care summary/download with logout protection. It also created a synthetic consumable, received five units, recorded use of two and verified three remained; these records existed only in the disposable test database. It also corrected a synthetic patient contact, verified attributed history and confirmed the corrected contact and explicit allergy status in the patient-facing summary. It created a synthetic invoice, recorded a payment, corrected the charges, reversed the erroneous payment entry and explicitly removed all charges, then verified preserved originals and shared summary history. The same reusable check also passed against the production Docker image. Temporary databases, the container, and its anonymous volume were removed afterward. Run `npm run test:production` after building; use `npm run test:production -- --image derma-platform:verify` to check a built container image.
